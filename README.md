# ✦ Interstellar Memory · 星间记忆

用于 SillyTavern 超长叙事对话的长期记忆扩展，基于《星间 · 长期记忆整理协议 v0.3》。

**当前版本：0.1.0，首次实机验证前的测试版。** 已核对 SillyTavern release 1.19.0 源码并通过本仓库自动化测试；尚未在用户实际酒馆与 Gemini 连接上完成端到端验证。

## 安装

在 SillyTavern 中打开「扩展 → 安装扩展」，粘贴：

https://github.com/Molly-0129/Interstellar-Memory

安装后刷新页面，打开一个单角色聊天。聊天输入区域会出现 **✦** 按钮；扩展设置中也有「星间记忆设置」入口。不需要安装依赖或服务器插件。

## 使用

点击 **✦ → 立刻大总结**。插件通过酒馆当前连接的模型，在后台发起独立整理请求。提示词不会作为用户消息插入聊天。

总结成功后，完整记忆作为最新一条消息出现：
- 已覆盖的旧正文与被接替的旧总结从模型上下文隐藏，原文继续保留在聊天记录中。
- 总结前最近四条未隐藏剧情暂时保留，通常是两轮问答。
- 总结后新增四条有效剧情消息，再隐藏先前暂留的四条。
- 当前有效总结始终受到保护。
- 每次整理前创建独立的完整聊天检查点；保存后从服务器读回核验，再改变隐藏范围。

「分卷总结」只处理已经整理过的历史记忆，达到阈值后开放。它按自然故事阶段归档较早历史，保留当前阶段、重要细节和活跃伏笔。若有新增正文，先做普通大总结，再按需要分卷；两种模式不会一起自动运行。

## 默认设置

| 设置 | 默认值 |
| --- | --- |
| 自动普通大总结 | 关闭 |
| 自动触发楼层 | 未隐藏剧情 ≥ 200 条 |
| 自动触发 Token | 同一批未隐藏剧情 ≥ 256,000 Token |
| 两个自动条件 | AND，同时满足 |
| 分卷解锁 | 有效记忆 ≥ 64,000 Token |
| 总结最大输出 | 16,384 Token，可调整 |
| 模型总窗口 | 使用酒馆配置，可手动填写 |
| 供应商强制 JSON Schema | 关闭；仅支持的 Chat Completion 模型可开启 |

设置仅作用于当前聊天。Token 由酒馆当前分词器统计，可能与模型供应商最终计费统计不同。请求容量预检包含输出和格式余量；超出时会停止，不会截断原文后宣称完成。

一层＝一条实际剧情消息。重生成、切换备选回复、续写同一消息不增加层数；总结、隐藏消息与工具调用不计数。特殊对话也严格暂留四条，不额外扩大范围。

## 两种整理方式

**普通大总结**保留旧记忆，通过增量追加与明确修订更新事件、人物、关系、秘密、物品、地点、未决事务和重要细节。未再次提及的旧记录不会因为模型遗漏而被删除。

**分卷总结**仅在记忆达到独立阈值后执行。所有历史单位必须完整、唯一地分配到归档卷或当前卷。不能自然归档、结果格式错误、来源引用错误或未达到容量目标时，保留旧记忆，不隐藏来源。超目标草稿保留在操作记录，可导出查看。

锁定文本逐字继承；其当前效力仍可据实变化，例如保留曾经的承诺，同时更新为「已履行」。

## 材料与界面

在设置中分别编辑普通总结与分卷提示词，也可以补充：
- 不压缩的用户锁定文本；
- 最新活跃伏笔清单；
- 独立保存的剧情档案；
- 整理需要的角色与世界设定。

正文内的剧情档案随正文参与整理；当前角色卡的基础描述、性格与场景会作为参考材料。首版不自动读写其他扩展的存储，也不修改角色卡、世界书或叙事预设。

插件操作面板继承酒馆 UI。消息美化由外部方案负责；插件不提供主题或天文皮肤。总结以稳定的基础折叠结构输出，供外部美化接入。

## 恢复与撤销

- **恢复中断操作**：使用已保存检查点恢复本次操作之前的记忆和隐藏状态，保留后来新增的聊天。
- **撤销上次整理**：还原上次整理前的记忆与隐藏状态，保留后续新剧情。
- **打开整理前检查点**：在独立检查点聊天中查看完整原文。
- **导出记忆与操作记录**：下载当前记忆、历史总结和恢复记录的 JSON。

已总结的正文发生编辑、删除或备选回复切换时，插件暂停后续隐藏。此时请打开整理前检查点，在分支中重新整理。修改已经生成的总结正文也会触发一致性保护。

检查点以「聊天名 - INTERSTELLAR 操作编号」保存为独立聊天，可能包含完整聊天内容。清理检查点前请确认不再需要恢复。

## 当前边界

- 首版开放单角色聊天，群聊暂未开放。
- 消息美化与其他扩展的存储联动不包含在本扩展内。
- 不自动把超出模型窗口的请求分批；容量不足会停止并保留原文。
- 世界书、向量检索和其他注入扩展可能独立召回旧信息；酒馆的消息隐藏标志不能约束它们。
- 不同标签页并行编辑同一聊天仍可能造成冲突；当前提供服务器读回校验，但不宣称对酒馆所有写入提供跨标签页原子事务。
- 结构和来源校验能降低遗漏风险，不能保证模型永远准确。跨卷不丢失引用也不等于每句摘要在语义上绝对完整。
