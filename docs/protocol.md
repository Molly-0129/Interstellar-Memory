# 原文总结协议 · 0.2.0

本版替换 0.1.0 的 JSON 增量协议、程序合并和程序渲染流程。

## 提示词

普通大总结和分卷大总结均采用用户提供的独立完整提示词。内置字符串与 docs/ordinary-prompt.txt、docs/archive-prompt.txt 一致，保留粘贴文本的反斜杠、缩进和措辞。

请求 systemPrompt 只包含选中的提示词或用户自定义提示词。没有共同前缀、增量契约、程序编号要求或 JSON Schema 输出约束。

输入材料包含旧总结原文、尚未覆盖的新剧情、角色卡基础资料、用户补充设定、剧情档案、活跃伏笔与锁定记录。用户材料以结构化数据传递，程序不先行概括材料。

## 输出

普通模式只接受一个 <星间大总结> 块，分卷模式只接受一个 <星间卷宗> 块，内部为 YAML。
校验外层标签、单一 YAML 文档、重复键、必要字段及字段类型；禁止别名展开和危险对象键。
接受模板世界状态列表位于根节点或嵌套于当前世界状态；不把一种布局转换成另一种布局。
不修复模型 YAML，不抽取 JSON，不删掉额外解释后尝试提交；校验失败保留原上下文。

原始响应直接作为聊天消息 mes 保存，包括原有空白。解析得到的 document 仅作为结构化存储，不反向生成正文。
memory 记录 schemaVersion、程序 revision、mode、raw 和 document；模型不返回或猜测程序版本号。
不合并、去重、重排或压缩模型的任何事件、卷宗、人物状态或重要细节。
不自动补写旧记录、重设卷号或追加锁定内容。用户锁定记录与伏笔输入继续独立保存在聊天设置中。

0.1.0 的旧总结及其恢复记录保持可读，下一次请求将旧总结消息原文作为历史基础提供给模型；不在升级时改写旧消息。

## 容量

分卷解锁阈值衡量当前有效总结消息原文。程序不按该阈值继续压缩或改写模型结果。
请求预检仍预留模型输出和格式余量，超过模型窗口时停止，不截断材料。

## 保存和隐藏

先创建并验证整理前检查点 → 模型生成 → 标签及格式校验 → 原文保存并服务器读回 → 提交有效版本与隐藏范围 → 再次读回确认。
当前有效总结不被隐藏；旧总结在新版本接替后与已覆盖正文一起退出上下文，原文留存。
最近四条剧情暂留，新增四条剧情后再隐藏。重生成、swipe 和续写同条消息不增加楼层计数。

coverage 只记录本次提供给模型的来源消息标识与指纹，供安全隐藏和编辑检测使用；它不证明模型在语义上完整保存了每项来源事实。

崩溃、取消、网络失败和保存不一致保留恢复入口，不跨聊天写入，不覆盖后续新消息。

## 自定义提示词与更新

已保存的 0.1.0 原始默认提示词按精确文本匹配自动切换为新默认值。用户自行修改过的内容不被覆盖。
0.1.0 的强制 JSON 输出开关不再使用；设置界面已移除该项。
